# AgentWMv3：Probe 训练计划（简明版）

这份计划的目标是：训练一个小分类器，在 Agent 执行动作前，判断“这一步调用环境模拟器，是否可能带来帮助”。它是后续工作的建议，不代表下面的数据已经采够，也不会自动修改现有实验配置。

## 1. 训练什么

Qwen3.5-9B 继续负责提出动作和审核动作，参数保持不变。真实环境模拟器、经验库也先保持不变。

只训练一个很小的 Probe。它读取 Qwen3.5-9B 生成决策时的中间层数值，输出一个“值得调用”的分数。这个分数开始时不是经过校准的成功概率。

第一版先用最简单的线性分类器。先确认这些数值里有没有可学习的收益信号，再考虑更复杂的 MLP 或注意力模型。

## 2. 训练数据怎么来

先在合法训练任务里，让相同模型分别运行 Never 和 Always，保存真实轨迹。优先回看 Always 成功、Never 失败的任务，同时保留双方成功、双方失败和 Always 更差的情况。

不能把 Always 的整条成功轨迹都标成正例。我们从早期、中期、后期抽取具体决策状态，既随机抽样，也关注重复动作、明显前提冲突等自然发生的疑难状态。不能人为制造错误动作来冒充真实采样成果。

每个选中的状态保存两部分：

- **输入**：当时的目标、观察、已发生的历史、候选动作，以及模型的中间层数值。
- **标签**：后面通过真实环境对照，得到这次调用有没有帮助。

未来反馈只能用于制作标签，不能提前进入 Probe 的输入。无法对齐、无法恢复或未完成的样本要单独记录，不填成零分。

## 3. 怎么判断这次调用有帮助

从同一个经过验证的环境状态，执行两个分支：

- **Skip**：直接执行原动作。
- **Call**：先在独立环境中试执行原动作，让固定 Reviewer 决定是否修订，再执行最终动作。

之后两个分支都使用同样的后续 Actor 策略、随机种子和剩余步数预算，比较真实的最终任务结果。

先做 3 个后续随机种子的对照；只要出现收益差异，就补到 5 个：

| 标签 | 判定方式 |
|---|---|
| 正收益 Help | 5 次里至少 3 次改善，且没有变差 |
| 负收益 Harm | 5 次里至少 3 次变差，且没有改善 |
| 零收益 Neutral | 复核的结果全无差异；未改动作的情况还要验证两条实际轨迹一致 |
| 不确定 | 结果摇摆、证据不足或对照未完成，不用于硬标签训练 |

这里的“改善”先固定为最终任务成功结果提高。动作能执行、动作被改了、任务整体成功，都不能单独证明这次调用有帮助。更快完成等效率收益先另外统计，不偷偷改成成功正例。

**一个状态做 5 次复核，仍然只是 1 个标注状态，不是 5 个独立样本。**上述规则是初步复核标准，不是统计显著性的证明。

## 4. 要准备多少数据

没有适用于所有 Probe 的统一最低数量。我们先按下面的目标起步，再通过学习曲线判断是否需要继续采样。

| 阶段 | 数据目标 | 用途 |
|---|---|---|
| 工程试跑 | 当前少量正例 | 检查代码、标签和训练链路，不宣称模型可用 |
| 第一版线性 Probe | 约 500–1000 个有效训练状态，其中争取至少 50 个正例，正例覆盖至少 10–15 个任务 | 看有没有初步可学习的信号 |
| 独立验证 | 另留约 200–300 个状态，争取有约 20 个正例，且不与训练任务重叠 | 选择模型、检查泛化 |
| 更复杂的 Probe | 线性结果有希望后，再考虑数千状态、数百正例 | 检查更大模型是否确有收益 |

这些数字是建议的起步目标，不是效果保证。当前的“5 个训练正例、2 个验证正例”只是代码能启动的工程门槛。

**100 个任务是第一批采集池的规模，不是 100 个正收益任务，也不是数据一定够的承诺。**目前确认的正收益候选只有 5 个，来自 4 个任务。

按此前采样观察到的约 1–2% 正例比例粗估，攒到 50 个正例可能需要复核几千个状态。这只是采集成本估算，不能当成线上正例概率。

可以在训练集中增加自然疑难状态、保留全部正例并对大量重复负例去重，形成最终训练集；但要记录采样方式，保留完整原始数据。不能复制同一个正例来假装增加独立证据。

## 5. 数据怎么隔离

训练集、验证集、阈值校准集、独立评估集和最终测试集分别使用不同的任务目标。同一个任务的不同步骤、变体和 Call/Skip 分支，都必须留在同一数据角色里。

目前先保留原有验证和校准任务，训练池扩到 100 个目标。需要继续增加数据时，只从合法训练池中选择并预先固定新的任务清单。

验证集要先固定任务和采样规则，不能为了凑正例挑有利案例。若验证证据不足，就报告不足，另行预注册扩充批次。最终测试集不参与任何训练、经验合成或调参。

同一任务里的多个状态不是完全独立的，因此除了状态数，还必须报告独立任务数。训练数据里富集了疑难案例，也不能据此宣称线上调用收益率很高。

## 6. 具体怎么训练

1. 保存冻结 Qwen3.5-9B 的真实决策及对应中间层数值，只使用执行当前动作前已经产生的信息。
2. 把每段决策的数值汇总成固定长度向量，先训练带正则化的线性分类器，预测 Help／非 Help。
3. 正例使用经复核的 Help；反例使用有证据的 Neutral 或 Harm；不确定样本不强行归类。
4. 处理类别不平衡时，只在训练集使用类别权重或负例抽样。归一化统计量也只用训练集计算。
5. 先训练少量候选配置和 3 个随机初始化，按独立验证结果选层和模型，报告所有种子的表现，不只挑最好的一次。
6. 用小、中、大几档训练数据画学习曲线，检查增加数据后验证结果是否改善。若只在训练集很好，说明可能记住了样本。

第一版重点先回答“Help 能不能被预测”。动作被环境拒绝的风险可以作为辅助任务，但它不等于调用收益；公开合法动作列表也必须作为简单对照。

如果没有足够的 Harm 样本，就不训练一个假的风险头，也不把缺失风险当成零。当前依赖 Help/Harm 两个头的 Utility Gate 不能因此自动部署；Help-only Gate 如需评估，应另设清楚的实验变体。

## 7. 训练后怎么检验

先检查离线预测：能不能找到更多真实 Help、误触发多少、是否只对少数任务有效，表现是否优于原有 NLL 信号。因为正例少，不能只看整体准确率。

模型选好后，才用单独的校准数据设置调用阈值和预算。初期分数只用于排序，不解释成真实成功概率；疑难样本富集造成的分布变化也要单独处理。

最后在新的独立开发任务上比较 Never、Always、NLL Gate、简单合法动作规则和 Probe Gate；再按设计加入冻结经验库对照。所有策略共享相同 Actor、Reviewer、Prompt、环境和步数设置。

同时报告任务成功率、LLM Tokens、额外模型前向、模拟器查询次数和耗时。Probe 的离线采集和训练成本单独列出。不能只说减少了 WM 调用，却不算新增成本。

独立开发评估通过后，才讨论正式 Test；当前不自动进入 Phase 6。训练任务上的结果、验证结果和独立评估结果必须分开报告。

## 8. 接下来按什么顺序做

1. 完成 Token 对齐修复和真实模型／环境回归验证，保留中断账本和原始数据。
2. 复用已完整完成的 47 个训练目标，补完原定剩余 13 个，再采固定新增 40 个，组成 100 目标训练池。
3. 统计实际得到的有效状态、正负例、独立任务覆盖和每个可靠标签的采集成本。
4. 数据仍少时，只做标明用途的工程试跑；继续按固定批次扩充合法样本，不降低正例标准。
5. 达到第一版起步目标后，先做线性 Probe 与学习曲线，再决定是否值得训练更复杂的模型。
6. 单独完成模型选择、阈值校准和新任务评估，验证是否真的在合理成本下提高调用收益。

最终要证明的是“这个小分类器能帮助系统更合理地使用模拟器”，不是“训练程序能跑出一个 checkpoint”。

## 参考思路

本计划借鉴 OpenAI 的“读取中间激活、监督训练小型分类器、触发后升级复核”思路。环境收益标签、数据配额和实验流程是本项目的设计，不是该文章给出的最低样本量，也不是复现其安全分类实验。
